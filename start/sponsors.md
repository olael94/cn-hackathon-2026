# Sponsor Playbook

Sponsors are usually the judges. Their test: "If we reward this, do we look good?"

## Before the event

- [ ] List every track: prize, real requirement (not the headline), judge
- [ ] For each sponsor tool: newest feature with few public demos
- [ ] Build one tiny practice project per sponsor tool you might use, so setup costs zero hours on the day
- [ ] Turn on the sponsor's Claude Code plugin if one exists (`.claude/settings.json`, set to `true`)

|       |       |                  |       |                    |

## Stack tracks

One build, several prizes. Niche tracks often have little competition.

- A tool counts only if it's core to the build, not bolted on. Judges spot a token integration fast.
- Pick tracks whose requirements share one demo moment (for example, one live "find and fix" moment that shows two observability tools at once).
- Drop the weakest track first if time runs short.

## During the build

- [ ] Hour one: ask each sponsor you're targeting, "If I built X, would that win?" Change course if the answer is lukewarm.
- [ ] Ask what they wish people built with their tool.
- [ ] Mid-build: show them the working path. A sponsor who has seen it early judges it warmer.

## In the demo

- Name the sponsor tool and the exact thing it did. Show it, don't list it.
- Make their tool look like the hero of one moment.
